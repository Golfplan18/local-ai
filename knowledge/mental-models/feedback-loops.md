# Feedback Loops

## Trigger

Invoked from within systems-analysis, growth-strategy, leverage-identification, and intervention-design modes when an analyst is examining a system's dynamic behavior — a trend that is accelerating, a stable system whose stability needs explanation, an intervention that produced unexpectedly large or small effects, or a virtuous or vicious cycle that the analyst wants to amplify or break. The host mode supplies the system and the variable of interest; the lens supplies the loop-tracing protocol that identifies reinforcing and balancing loops, plus the intervention rule that strengthening any link in a reinforcing loop accelerates it while weakening the weakest link breaks a vicious cycle.

## Core Structure

### Core Insight

A feedback loop exists when the output of a system feeds back as input, either amplifying the original signal (reinforcing loop) or dampening it (balancing loop). Reinforcing loops drive exponential growth or collapse. Balancing loops drive stability around a setpoint. Most non-trivial system behavior — booms, busts, plateaus, oscillations — is generated by the interaction of these two loop types, often with delays that produce overshoot and undershoot patterns.

### Mechanism

In a reinforcing loop, an increase in the variable of interest leads (through one or more intermediate steps) to a further increase in the same variable. The loop can run virtuously (more users → better content → more users) or viciously (more bugs → more rushed fixes → more bugs). In a balancing loop, an increase in the variable triggers an opposing change that returns the variable toward a setpoint (high inventory → reduced ordering → lower inventory). Real systems typically contain multiple loops of both types; the dominant loop changes over time as the system evolves, producing characteristic behavior patterns (S-curves, oscillation, collapse).

### Applicability Conditions

- The variable of interest can be observed over time, not just sampled at one point.
- The downstream effects of the variable plausibly loop back to affect the variable itself.
- The time-scale of the loop is within the analysis horizon.
- The system is dynamic enough that loop behavior dominates static structural features.

### Common Misapplications

- Treating a sequence of events as a loop when no actual feedback path exists (post-hoc narrative pattern that mistakes correlation for causal feedback).
- Identifying only one loop when multiple loops compete; the dominant loop changes the analysis materially.

### Related Models

- **Systems Thinking** — the broader discipline of which feedback-loop analysis is the core technique.
- **System Archetypes (Senge)** — named patterns of multi-loop interaction.
- **Leverage Points (Meadows)** — where in a loop structure to intervene for maximum effect.

## Application Steps

1. Identify the key variable to track (users, revenue, code quality, morale).
2. Trace what happens when that variable increases — what else changes?
3. Follow the chain: does the downstream change eventually increase the original variable (reinforcing) or decrease it (balancing)?
4. Map the loop explicitly; draw it.
5. To accelerate a reinforcing loop, strengthen any link in the chain; to break a vicious cycle, weaken or sever the weakest link.

## Detection Signals

- A trend is accelerating and the cause is not obvious.
- A system has been stable for a long time and the analyst wants to understand the source of stability.
- An intervention produced a surprisingly large or surprisingly small effect.
- A system is being designed and its long-term behavior must be predicted.
- A virtuous or vicious cycle is visible and the analyst wants to amplify or break it.

## Critical Questions

- Is there an actual feedback path, or is the analyst pattern-matching a sequence that lacks closing the loop?
- Have all material loops been identified, or only the most visible? The dominant loop changes the analysis.
- Are time delays between cause and effect being represented, or is the analyst assuming instantaneous propagation?
- Has the analyst tested loop predictions against historical behavior, or is the loop diagram only suggestive?

## Common Failure Modes

- **Phantom loop** — Detection signal: a loop is drawn but the closing link cannot be defended causally. Correction: state the closing-link mechanism explicitly; if it cannot be defended, remove the loop from the analysis.
- **Single-loop tunnel vision** — Detection signal: the analysis is built on one loop while a competing loop changes the dynamics. Correction: identify all material loops; assess which dominates under current conditions.
- **Delay neglect** — Detection signal: predictions assume fast feedback when the actual loop has delays of months or years; predictions miss timing badly. Correction: represent delays explicitly.
