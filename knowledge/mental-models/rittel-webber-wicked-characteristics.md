# Rittel Webber Wicked Characteristics

## Trigger

Invoked when wicked-problems analysis needs to determine whether a situation is genuinely wicked rather than merely hard. The host mode supplies the problem and stakeholder field; the lens supplies Rittel and Webber's characteristics.

## Core Structure

Wicked problems are planning problems whose definition, solution, and evaluation are entangled with values, stakeholders, and consequences.

Key characteristics include:

1. No definitive formulation.
2. No stopping rule.
3. Solutions are better or worse, not true or false.
4. No immediate or ultimate test of a solution.
5. Every intervention is consequential and hard to reverse.
6. No enumerable set of possible solutions.
7. Each wicked problem is essentially unique.
8. Each is a symptom of another problem.
9. Explanations depend on worldview.
10. Planners have no right to be wrong in the way scientists can test and fail.

## Application Steps

1. State the problem formulation currently being used.
2. Test which wicked characteristics are present.
3. Identify stakeholders whose values change the problem definition.
4. Identify irreversible or high-consequence interventions.
5. Identify linked problems and symptom relationships.
6. Recommend governance, iteration, and learning rather than one-shot solution.

## Detection Signals

- Stakeholders cannot agree on what the problem is.
- Every proposed solution changes the problem.
- Success criteria are contested.
- The issue is embedded in broader systems and values.
- A technical solution is being asked to settle a political or moral dispute.

## Critical Questions

- Who defines the problem, and who contests that definition?
- What counts as improvement, and for whom?
- What intervention cannot be cleanly undone?
- What larger problem is this a symptom of?
- Which worldview makes this explanation seem obvious?

## Common Failure Modes

- **Hard-wicked confusion** - Detection: complexity alone is treated as wickedness. Correction: test value contestation and problem-definition instability.
- **Solutionism** - Detection: a technical fix is offered for a value-conflict problem. Correction: add governance and stakeholder process.
- **Infinite-analysis trap** - Detection: wickedness becomes excuse for no action. Correction: use provisional action with learning loops.
- **Stakeholder erasure** - Detection: one party's formulation is treated as neutral. Correction: surface competing formulations.
