**Structural definition.** A `state` envelope is a finite-state machine rendered from a Mermaid `stateDiagram-v2` string. PROCESS family, Path A (Mermaid). `spec` has EXACTLY two keys: `dialect` (const `"state"`) and `dsl`. `additionalProperties:false` — no `direction`, `title`, `nodes`, `theme` keys in `spec`; layout direction goes INSIDE the dsl as a `direction LR` line, never as a sibling field (this is the documented `.invalid.json` trap).

**state vs the siblings it gets confused with.** Use `state` when nodes are *modes/statuses an entity rests in* and edges are *events/conditions that move it between them* (account is Active vs PastDue; order is Pending vs Shipped). Use `sequence` for messages between actors over time; use `flowchart` for a decision/activity procedure where boxes are *actions* not *resting states*. If your "states" are verbs (Validate, Send) it's a flowchart, not a state machine.

**The exact failure modes the judge flagged (defeat these):**
1. **No final state.** Low scorer had no `[*]` sink. ALWAYS declare an initial `[*] --> First` AND at least one terminal `Last --> [*]`. Winners all had the filled start dot + final ring.
2. **Crossed / mis-directed edges (Active<->PastDue confused).** Author transitions in a consistent flow order and double-check each arrow's direction matches its event semantics. A recovery edge must point BACK toward the healthy state, not forward.
3. **Dangling self-loop ("Maintain" on one state).** No `X --> X` cosmetic loops. Every edge must encode a real event. Every state must be reachable from `[*]` (unreachable states are flagged downstream).

**Layout + labeling rules.** Top scorers carried **guarded, event-bearing labels** on transitions: `State --> State : event [guard]` (e.g. `trial_ends [payment_method valid]`, `cure_window elapsed [>14 days]`). Bare arrows score lower. Keep ~4–6 states for legibility; put a recovery/won-back loop in if the domain has one (judges rewarded the re-billing loop). Begin dsl with `stateDiagram-v2`; optional `direction LR` as the next line (inside dsl). `semantic_description`: level_1 counts states/transitions, level_2 names the most-connected state + true sinks + how many guards, level_3 the perceptual funnel-with-loops gestalt; `short_alt` ≤150 chars naming THIS machine, never "bar chart" boilerplate.
