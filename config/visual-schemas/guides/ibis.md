STRUCTURE. IBIS = typed argument graph for a wicked/contested question. Four node `type`s: `question` (the issue), `idea` (a candidate position/response), `pro` (argument for), `con` (argument against). Four `edge.type`s with a STRICT grammar (blocking if violated, §3.12): `idea --responds_to--> question`; `pro --supports--> idea`; `con --objects_to--> idea`; `question --questions--> any` (sub-issues only). Edge `from`/`to` are node `id`s. Every idea must `responds_to` a question; every pro/con must attach to an idea, never directly to the question. Render path: ARGUMENT family, semantic JSON → DOT; mode `dialectical-analysis`.

BUILD THIS vs SIBLINGS. Use IBIS when ONE contested question has MULTIPLE competing positions, each with its own support/objection — a deliberation map. Degrades into `pro_con` when there is a single claim with two columns (no rival ideas, no issue node) — cue: if you cannot name ≥3 distinct candidate answers, it is pro_con. Degrades into a prose dialectical essay when no graph is emitted at all — always emit nodes+edges.

JUDGE FAILURE MODES DEFEATED. (1) Thin/binary map — fixed by populating ≥3 ideas (target 3-4) each with ≥1 pro and ≥1 con, plus one sub-`question` via `questions` to show frame-conflict depth. (2) Prose-essay-no-map (qwen lane scored 2.3) — fixed by ALWAYS shipping the spec graph, never just narrative. (3) ~11:1 illegible-wide layout (premium lane) — fixed by capping breadth: 3-4 ideas, NOT 8; one sub-issue, not many; keep `text` short (≤8 words) so DOT nodes stay compact and the aspect ratio stays readable.

LABELING. `question.text` is a genuine question (ends "?"). `idea.text` is a noun-phrase position. `pro`/`con` texts are single crisp claims, not paragraphs. Unique short ids (Q1,I1,P1a). Set `relation_to_prose:"integrated"`. semantic_description must describe the ARGUMENT MAP (issue, count of positions, pro/con balance), never a chart.
