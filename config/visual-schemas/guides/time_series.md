**Structural definition.** A time_series is a QUANT-family Vega-Lite spec (render Path A) with a TEMPORAL x-axis (`encoding.x.type:"temporal"`) and a quantitative y. It plots ordered measurements of one quantity over time as a `line` (or `area`/`point`). The Ora `spec` schema REQUIRES top-level `$schema`, `data`, `mark`, `encoding`, `caption` — even when you also supply a `layer` array. Omitting top-level `mark`+`encoding` is the #1 schema failure (envelope `oneOf` rejects the whole thing). Keep a minimal top-level `mark:{"type":"line"}` + `encoding.x/y`, and put band/MA/annotation layers in `layer`.

**time_series vs siblings.** Use it (not comparison/bar) when x is a date/ordered period and the message is trend/rate/trajectory. Use it (not scatter) when one axis IS time and points are sequential, not a bivariate cloud.

**Failure modes from judge notes — design against these.** (1) The line is correct but the prescribed MA overlay is OMITTED — models draw the raw line only. ALWAYS add the moving-average as a second `layer` line (distinct color/width) when prose mentions smoothing/deceleration. (2) The event annotation (e.g. "Q3-2025 pricing change") is OMITTED — satisfies T13. ALWAYS add a `rule` mark at the event date + a `text` mark labeling it. (3) Tiny/unrealistic y-scale (`v:1,2`) destroys realism — use REAL business magnitudes (hundreds of thousands / millions). (4) Shape over-tells: a "deceleration" story must render concave-down-but-still-rising, NOT a downturn — make later month-over-month deltas shrink toward zero, never negative.

**Layout + labeling rules.** Banking-to-45 (T10): set `width`~720 `height`~270 (aspect ~2.5–2.7) so the dominant slope is near 45°; mirror in `render_hints.aspect_ratio`. Zero-baseline ok for a line (T2 binds bars/area); if you clip the y-domain set `integrity_declarations.non_zero_baseline_justified`. T7/T15: caption needs `source`,`period`,`n`,`units` AND axis `title`s. T12: currency over >3yr → say "real/deflated" in units. Forecast/projection mode → MANDATORY uncertainty band (`errorband` with `y`=lo,`y2`=hi); distinguish actual vs forecast via `strokeDash`. Never dual independent-zero y-axes. semantic_description: all three levels + a short_alt that describes THIS series (start/end values, the bend), not "line chart" boilerplate.
