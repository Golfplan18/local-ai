**Structural definition.** A flowchart is a PROCESS-family diagram: `spec.dialect` MUST be `"flowchart"`, `spec.dsl` is a single VALID Mermaid `flowchart` string (Path A — raw Mermaid, no semantic JSON). It maps an actual procedure step-by-step from a start terminator to one or more end terminators, branching at decision diamonds.

**THIS type vs. its confusable siblings.** Flowchart = *how work flows / who does what next* (operational procedure, ordered, with role lanes). Use a **decision_tree** instead when branches carry probabilities/payoffs and you want rollback EV (flowchart has none). Use a **state** diagram when nodes are persistent statuses of one entity with event-triggered transitions, not work steps. Use a **sequence** diagram when the point is message exchange/timing between actors. The flowchart's distinguishing asset (per judge notes): **typed swimlanes** — `subgraph LaneId[Lane Name] ... end` — assigning each step to a role. The four top-scoring renders were all 4-lane swimlanes.

**The specific failure modes the judge punished.**
1. *Empty/invalid `dsl`* — the fixture's `dsl:""` fails `minLength:1`. Always emit a real graph.
2. *Decision node with one exit* — every `{...}` diamond MUST have ≥2 labelled, mutually exclusive, exhaustive outgoing edges using `-->|label|`. PROCESS structural rule (§7) blocks render otherwise. Two-way diamonds need both yes AND no.
3. *Overloaded/cramped render* (premium dinged) — keep node labels SHORT (≤4 words), prefer `flowchart TD`, avoid crossing edges; converge branches on a shared node rather than duplicating downstream steps.
4. *Bottleneck named only in prose* (qwen/optimum-plus shortfall) — the WINNER marked the bottleneck ON the canvas. Add a `classDef` and apply it (`Node:::bottleneck`) to flag the constraint/deviation in red directly in the diagram.

**Layout + labeling rules.** Use typed shapes deliberately: `([Terminator])` for start/end, `[Rectangle]` for actions, `{Diamond}` for decisions. One start terminator; explicit terminal end(s) for each outcome (Paid, Rejected). Lanes as `subgraph`. Branch every edge label. Fill `title` and `caption` (source/period/n). `mode_context:"process-mapping"`, `relation_to_prose:"integrated"`. `semantic_description` needs level_1/2/3 (4 optional) describing THIS process and a `short_alt` ≤150 chars naming the actual lanes and the flagged bottleneck — never bar-chart boilerplate.
