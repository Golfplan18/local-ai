The canonical wrong output is a 3–5-point monochrome "toy" scatter whose color channel collapses to a legend reading "undefined" — points render in one default hue, no regions are distinguishable, and the 4 data points are too sparse to substantiate (or even contradict) the cluster claim the prose makes. A second degraded form is silently swapping into a bar/comparison chart (one categorical axis) because the copied semantic_description still says "Bar chart of four categories." The single rule that prevents both: emit 20+ realistic rows over BOTH quantitative axes, give encoding.color an explicit field + nominal type + scale.domain/range covering every category, set caption.n to the exact row count, and write a level_1_elemental that names THIS scatter's two measured variables — never bar-chart boilerplate.
